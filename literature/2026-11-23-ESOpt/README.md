# 从一次选优到多轮更新：八篇论文阅读笔记

阅读范围为 11 月 23 日交接中链接的八篇论文，PDF 文件名保留 arXiv 版本。下文的效果数字来自论文；本组的实测数据见[三个实验的交接](../../experiments/2026-11-23-实验交接.md)。[Sudoku 复现建议](Sudoku复现建议.md)单列了官方实现、效果与预算。

## 1. Evolution Strategies at Scale

**问题与方法。** 对数十亿参数的语言模型，只能观测生成结果的奖励时，全参数搜索能否积累改进？在当前模型附近采样高斯扰动，每个方向在一批题上取得一个平均奖励。按当轮种群均值和标准差标准化奖励，再把对应噪声向量加权写入中心模型。下一轮从更新后的中心重新采样。作者在推理、简洁性优化等任务上比较了 ES 和梯度式 RL。

**巧处。** 各推理进程只需共享随机种子和标量奖励。更新时逐层从种子再生噪声，省去传输或保存一整套候选权重的成本。代价转移到大量前向评估。这给本组一个最直接的对照：同一批方向、同一批题，一边选最佳单模型，一边合成中心，再比较两者在新题上的表现。[PDF，算法 1–2](papers/2509.24372v3.pdf) · [作者论文](https://arxiv.org/abs/2509.24372v3)

## 2. CoRP · Consolidating Rewarded Perturbations for LLM Post-Training

**问题与方法。** 高分扰动之间是否有可以写回一份权重的共同成分？作者把高分扰动随机分半，比较两半的低秩结构。CoRP 先用高奖励方向提出合成方向，再按各方向与提案的对齐程度和正交分量重新加权。用独立验证折检查增益，证据弱时保留原模型。五个模型、五项任务的汇总中，单次推理相对基线平均提高 8.1 个点。

**巧处。** 一个方向可以独自取得高分，却在求和时抵消其他方向。CoRP 给“它表现得好”和“它适合与别的方向合并”各做一次测量。对 WebShop，先检查独立任务子集上的增益是否同向，再决定是否值得试兼容性加权。84 题矩阵能看奖励的一致性，几何兼容性还要用实际权重方向。[PDF，§3–4](papers/2605.31494v2.pdf) · [作者论文](https://arxiv.org/abs/2605.31494v2)

## 3. ZO-Agent · Beyond the Capability Boundary

**问题与方法。** 在困难搜索题上，原模型反复采样都得不到成功轨迹，下一轮拿什么训练？作者逐题扰动 LoRA，用扰动前后的损失差估计更新方向，再从适配后的策略采集成功轨迹，用 SFT 将经验写入共享模型。零阶优化负责探索，跨题积累则依靠监督训练。

**巧处。** 同一轨迹中，把末尾答案替换为已知正确答案，计算该答案在轨迹上下文中的负对数似然。即便两次回答都错，也可能得到不同的连续信号。多方向推理还可复用匹配的搜索或网页访问结果。移到苹果任务时，要先界定训练阶段能取得什么监督。模型实际看到的柜内物品可以作为依据，环境内部的苹果真实位置若被使用，应单列为额外监督。[PDF，§3.2–3.5](papers/2608.09292v1.pdf) · [作者论文](https://arxiv.org/abs/2608.09292v1)

## 4. Agentic ESOpt

**问题与方法。** 多轮决策后才有一次终局反馈，能否用它更新执行整条轨迹的模型？当轮固定一批任务，让每个扰动模型完成整局，按批平均分给方向赋权并更新中心。Sudoku 随训练逐步缩小扰动幅度，15 空格实验保留非零末值。控制空格数使作者能改变最短成功步数，同时保留相同动作接口和终局评分。

**巧处。** 外部程序能以两种方式参与优化。启发式设计中，模型在线提出程序，程序执行得分同时推动程序搜索和生成模型更新，36 组比较中有 28 组改进。WebArena-Lite 则先以 No Skill 完成 70 轮 ES，再一次性把轨迹提炼成技能。27B 模型的 No Skill 成功率由 29.47% 到 36.16%。这个网页结果支持分阶段组合，两种部件能否在连续多轮互相促进仍值得单测。[PDF，表 1、4、13 和启发式设计实验](papers/2608.17310v2.pdf) · [作者论文](https://arxiv.org/abs/2608.17310v2)

## 5. Asynchrony Is Nearly Free for Evolution Strategies on Long-Horizon LLM Agentic Tasks

**问题与方法。** 快进程等慢进程会浪费时间，但迟到的奖励是从旧中心测得的，还能使用吗？作者在 Qwen3-4B-Instruct-2507 + WebShop 上比较同步 ES、有限滞后的异步 ES，并分别控制迟到更新的年龄和占比。16 个方向 × 16 题、200 轮的配置中，同步和自然异步最后的精确成功率分别为 72.7% 和 71.9%，基于固定的 128 道监测题。

**巧处。** 把“迟了几轮”和“一次更新里有多少旧分数”分开操纵，能比单看运行速度更清楚地解释结果。对本组更重要的是其同步基线：训练奖励为两倍部分分加八倍满分指示，主指标是精确成功率。我们的 Qwen3-4B 使用另一份模型快照，0.5118 是官方终局**均分**。复用自己的 Harness 时可同时报告均分和满分率；若更换奖励、解码和商品库，要记录这些变化后再解释差距。[PDF，§3–4、附录 D.1](papers/2610.04196v2.pdf) · [作者论文](https://arxiv.org/abs/2610.04196v2)

## 6. WHALE · A Simple Recipe for Joint Harness-Weight Optimization

**问题与方法。** 模型学会新行为后，原先最好的 Harness 可能不再适合它。WHALE 固定当前 Harness，保留成功轨迹做在线拒绝采样微调；再冻结更新后的模型，以 Meta-Harness 搜索可执行的外部代码。作者比较了单独优化、先后各做一次、短周期交替等设置，在搜索问答、数学、棋题上评估。

**巧处。** 何时换阶段本身会影响训练。作者同时测试固定周期，以及在最短阶段长度后、训练信号连续不再改善才切换的规则。数学实验中，先更新权重后 Harness 搜索才有收益。可借鉴的是保存每一轮的新旧组合，分别测“模型变化后，哪种提示才开始有用”和“提示拿掉后，模型还会多少”。[PDF，§3–5](papers/2609.00196v1.pdf) · [作者论文](https://arxiv.org/abs/2609.00196v1)

## 7. CoHARL · Co-Evolving Agent Policies and Executable Harnesses with Reinforcement Learning

**问题与方法。** 如果训练始终由单一 Harness 生成轨迹，可能只探索一种交互方式。CoHARL 维持多份可执行 Harness，让同一执行策略从整个池的 rollout 做组内相对奖励更新，另由提案模型参考成功、失败轨迹修改 Harness。SWE-rebench 上解决率为 27.6%，比只搜索 Harness 高 6.4 个百分点。

**巧处。** 给某份 Harness 更多使用机会时，要校正它抽到的题有多难。调度器以每题历史表现为参考，扣除低使用次数带来的不确定性，并给新版本试用机会。调度分决定谁获得更多数据，执行模型的训练优势另算。对本组，这是一个可先在小规模实现的对照原则：比较两份 Harness 时配对同题，保留真实任务完成率验收过程指标。[PDF，§3、附录 C](papers/2610.36469v1.pdf) · [作者论文](https://arxiv.org/abs/2610.36469v1)

## 8. Evo² · Evolving the Evolver through Weight-Harness Co-Evolution

**问题与方法。** 怎样让提出 Harness 修改的模型越来越擅长改进系统？同一个策略分别担任提案者和反思者。每次修改实际执行并评估，再以修改前后的效果监督提案和反思，通过 SFT 与两种角色交错进行的 GRPO 训练改进者。

**巧处。** 一次改动序列即使后段格式出错，前面成功应用的修改仍有价值。作者恢复到最后一个有效版本，从该处重新生成后缀，对修复后的程序重新验收。评价反思者时，还观察采纳意见后的修改是否真的更好。若转向改进者路线，应在新任务上固定执行者和修改预算，测它写出的 Harness 能多解决多少任务。现有三个实验衡量的是执行者。[PDF，§3，尤其 §3.3.1](papers/2610.13025v1.pdf) · [作者论文](https://arxiv.org/abs/2610.13025v1)
