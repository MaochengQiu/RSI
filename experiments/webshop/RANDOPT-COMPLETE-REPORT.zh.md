# Qwen3-4B 局部与全模型随机扰动实验报告

实验在 RTX 5060 Laptop GPU（8 GB）上完成。最终补充评测日期为 2026-11-22。

**封存题结论。** 全局候选在 60 道新题上平均得 0.4958，原模型得 0.5118。逐题配对分差为 **−0.0160**，95% 区间 **[−0.0688, +0.0319]**。动作在 18 题上发生变化，只有 3 题升分，5 题降分。两组满分数均为 15/60。

## 1. 研究问题与实验设置

最初的问题是，固定提示、动作接口和解码，只改 Qwen3-4B 的一小块权重，Agent 的前向计算和实际行动是否会变化。随后把问题推进到任务效果：这些变化能否提高完成质量，开发题能否挑出在新题上更强的候选，扩大扰动范围后候选分布会不会变好。

| 项目 | 实际设置 |
|---|---|
| 模型 | Qwen/Qwen3-4B，修订 `1cfa9a7208912126459214e8b04321603b3df60c` |
| 推理 | 主体 NF4、双重量化、FP16 计算。第 18 层 `v_proj` 和共享 Embedding／输出头保留浮点 |
| 软件 | WSL2 Ubuntu 24.04，PyTorch 2.8.0+cu128、Transformers 4.57.6、bitsandbytes 0.50.2、Accelerate 1.10.1 |
| ALFWorld | ALFWorld 0.4.2、TextWorld 1.7.0。每次按同一 game file 重建会话，最多 50 轮 |
| WebShop | 官方文本环境修订 `64fa2a5c15c7daa698b9ac93f5bb5437b634c9bd`，固定商品、价格和 Lucene 索引，每题重置会话，最多 16 轮 |
| 解码与日志 | 单样本贪心解码，关闭采样和 thinking。输入最多 4096 token，单轮输出最多 64 token。保留提示、原始文本、实际动作或拒绝、前后页面、下单和官方终局分 |

## 2. ALFWorld 验证流程

先在目标矩阵 `model.layers.18.self_attn.v_proj.weight` 写入相对于原权重 RMS 约 1% 的加性高斯噪声。绝对 σ 为 0.000244625，FP16 写回后实测相对 Frobenius 变化为 0.99947%。同输入原模型连续前向差为零。扰动后目标层输出 RMS 差为 0.00652，末 token logits RMS 差为 0.01044。恢复权重后两处差值均回到零。

| 场景 | 原模型 | 扰动模型 | 首次环境动作不同 | 两边环境步数 |
|---|---|---|---|---|
| Book → SideTable，329 | 成功 | 成功 | 无 | 10 / 10 |
| ButterKnife 清洁后 → CounterTop，8 | 成功 | 成功 | 无 | 7 / 7 |
| Apple 冷却后 → CounterTop，14 | 失败 | 失败 | 无 | 49 / 49 |

小扰动已经进入前向计算，三局的贪心环境动作仍逐步一致。ALFWorld 提供了局部扰动、回写和恢复的可复现流程。完整场景 ID 和每轮日志在 [ALFWorld 归档](<D:/RSI-outputs/alfworld/compare-01>)。

## 3. WebShop 强度与下单时机

首库 20 条开发指令上，原模型 15 局下单，11 局获部分分，3 局满分，1 局买到零分。保留全部题目。固定三个方向，沿用同一单层目标矩阵。

| 绝对 σ | 动作变化（60 个配对） | 升分 / 降分 | 平均官方分 |
|---|---:|---:|---:|
| 原模型 | — | — | 0.4575 |
| 0.0002446 | 1 | 0 / 0 | 0.4575 |
| 0.0012231 | 13 | 4 / 1 | 0.4936 |
| 0.002 | 23 | 7 / 2 | 0.5019 |
| 0.003 | 28 | 10 / 2 | 0.5186 |

筛出的两个 5% 候选在首批 40 道留出题上的平均优势缩到 +0.0050 和 +0.0033。之后在同库另一批 38 道新题上配对比较原模型、5% 和 σ=0.003。强扰动把动作变化从 24/114 增到 57/114，但相对原模型升分和降分各 13 个，最终下单和满分总数与基线相同。

固定商品、规格和提示历史后，在 17 个可以立即满分的页面上按三个方向配对。原模型立即购买 30/51 次，5% 扰动 28/51 次，σ=0.003 为 25/51 次。加大 σ 后，一些方向更倾向继续找，另一些更倾向立即买。因此动作变化可能反映方向特有的偏好。好的例子是先选正确的粉色再下单，坏的例子是放弃满分商品并用完步数。固定页面上的直接对照没有显示判断何时下单的能力提高。具体题目和变化见 [强度扫描](<D:/GitHub/RSI/experiments/webshop/strength-01/strength-summary.json>) 与 [下单对照](<D:/GitHub/RSI/experiments/webshop/checkout-holdout-02/summary.json>)。

## 4. 筛选可靠性与扰动范围

在第二个万件商品库中，预先切出 24 道开发题和 60 道不同目标商品的新题。固定 σ=0.003 抽八个方向。开发集胜者 `1576763381` 在开发集得 0.6250，原模型为 0.6354。新题上胜者得 0.6030，原模型为 0.6092，预先指定的随机对照得 0.6509。出现了开发集与新题的排名反转。

在原预登记 `707798d` 下，20 局旧基线跨会话逐轮复现，包括生成原文。之后补跑另外六个方向各 60 局，组成原模型加八方向、84 道题的完整矩阵。这 84 道题用于方法研究。

- 八方向的平均分差为 −0.0149，95% 区间 [−0.0429, +0.0125]。估计的方向间真实效应标准差为 0.0136，区间 [0, 0.0903]。最好方向为 +0.0260，校正区间 [−0.0435, +0.0954]。原预登记的三态判定为**证据不足**。
- 1,000 次随机对半划分的第一名一致率为 25.8%，平均 Spearman 相关为 0.303。1,000 次用 24 题选择、在余下 60 题评价的模拟平均差为 −0.0052，42.8% 划分出现负收益。模拟共享同一批题。
- 在相同 24 道开发题上，比较单层、所有层 `v_proj` 和全模型三个范围。多层与全模型沿用相同固定前缀、末尾 16 个位置上的全词表 Token KL 目标 0.008649（校准）和 0.009102（复核），并用 ±10% 和 ±20% 容差。多层八方向均通过。全模型覆盖 251 个 NF4 矩阵和 147 个 FP16 张量，含 Attention、MLP、RMSNorm 和共享 Embedding／输出头。八个方向中七个通过，另一个复核 KL 高约 25%，仅完成校准。两组为独立随机方向。

| 同 24 题 | 方向数 | 相对原模型平均分差 | 最好方向分差 | 动作变化 | 升分 / 降分 |
|---|---:|---:|---:|---:|---:|
| 单层 `v_proj` | 8 | −0.0505 | −0.0104 | 76/192 | 12 / 22 |
| 所有层 `v_proj` | 8 | −0.0172 | +0.0347 | 52/192 | 9 / 14 |
| 全模型 | 7 | −0.0224 | +0.0104 | 62/168 | 7 / 11 |

小开发集排名不稳定有直接证据，方向平均收益偏低也有观测支持。单层、多层、全模型的样本量和随机方向不同，表中结果仅支持描述本次候选分布。完整分差与轨迹在 [84 题矩阵](<D:/RSI-outputs/webshop/randopt-followup-01/analysis/84-scores.csv>)、[多层分析](<D:/RSI-outputs/webshop/randopt-followup-01/analysis/scope.json>) 和 [全局记录](<D:/RSI-outputs/webshop/randopt-global-01>)。

## 5. 第三库 60 道封存题

这 60 道人工指令在补跑 360 局之前封存。第三库与开发库使用同一版本 WebShop 数据，各有独立的万件商品库和索引。封存时按目标商品和规范化指令排除了重合。此次按用户要求追加评测，保留原预登记的三态结果。候选只在新题开跑前从全局组确定一次，取开发集平均分最高的 `1732518584`，绝对 σ 为 0.0002578125，开发集比原模型高 0.0104。该方向的校准 KL 为 0.009224，复核 KL 为 0.010345。

量化矩阵沿用原 NF4 计算路径，并在前向中加 FP16 高斯线性增量。其余权重在 FP32 加噪后写回 FP16。共享 Embedding 和输出头使用同一份扰动，浮点权重在每个候选结束后恢复。开跑前核对了模型、环境、商品库、索引、价格和封存清单。零增量前向、非零扰动重复前向和恢复都通过检查。约定按题配对计算终局分差，使用 100,000 次整题重采样给出 95% 区间。

首轮运行发现第 75 号题的商品页含 225 个可点选项，当前页面单独已超出 4096 token。两组共用的修复仅在超长时缩短当前页，优先保留任务指令和可执行动作。正文保留首尾，菜单单独过长时优先保留下单与导航。已完成的八局原模型结果复用，异常局从初始状态重跑，原部分轨迹和旧清单单独归档。这项修改发生在原模型开跑后、候选开跑前，具体触发位置可从提示中的标记核对。[补充评测方案与复跑命令](<D:/GitHub/RSI/experiments/webshop/RANDOPT-FINAL.zh.md>)

| 封存集指标 | 原模型 | 冻结全局候选 |
|---|---:|---:|
| 官方终局均分 | 0.5118 | 0.4958 |
| 下单 | 51/60 | 50/60 |
| 满分 | 15/60 | 15/60 |
| 每题平均有效动作 | 6.80 | 7.23 |
| 每题平均模型轮次 | 7.05 | 7.48 |
| 每题平均搜索 | 1.42 | 1.48 |
| 每题累计输入 token 均值 | 7,410 | 7,923 |

| PyTorch 峰值分配显存 | 3.44 GiB | 5.06 GiB |

冻结候选比原模型 **3 题升分、5 题降分、52 题同分**。新增和丢失满分各 2 题，新增下单 1 题、失去下单 2 题。两组都只有第 75、11 号题触发超长页面处理，各 28 次提示缩短，两题终局分在组间均相同。全部 60 题是主要结果。只检查未触发的其余 58 题时，均分差仍为 −0.0165。

## 6. 结论

1. **扰动是否进入计算并改变行为。** ALFWorld 的固定输入和恢复检查证实扰动进入计算。WebShop 证实它能改变搜索、选品、规格和结账。在封存题上，18 道动作改变只有 8 道转化为终局分差。
2. **候选是否在新题上更强。** 这一个全局方向在开发集取得 +0.0104，在第三库封存集得到 −0.0160，区间跨零，也未达到 +0.03 实用门槛。其耗时约为原模型的 3.10 倍，包含本机按层重建全模型增量的额外计算成本。
3. **瓶颈与范围。** 随机方向的筛选排序对题目敏感。三种范围在同批开发题上平均均低于原模型。结果支持“小开发集筛选噪声”和“候选质量有限”同时存在，现有数据无法定量区分各自贡献。
4. **可推广范围。** 第三库同时改变了任务和商品库，检验的是这个固定候选的跨库表现。60 题的估计仍允许小幅正收益或负收益。更大模型、其他任务和其他候选生成方式需要自己的对照证据。
