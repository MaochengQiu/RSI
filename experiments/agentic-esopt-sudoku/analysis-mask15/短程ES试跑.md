# Sudoku 一轮 ES 与候选留出复评

运行 `observable-es-01` 于 2026 年 11 月 24 日完成。用 RTX 5060 Laptop 8 GB 串行评估。中心为 4-bit 作者 Mask15 checkpoint，从其中仍以浮点存储的 178 个张量、636,660,736 个参数上产生四个扰动方向。扰动尺度 0.0007，标准 ES 更新步长 0.0005，方向奖励为开发题终局成败的均值，再按官方实现做 z-score。该设置检验本机记录和重放链路，论文训练使用全参数。

开发和留出各用四道官方题，每组各含两道 Mask5 与两道 Mask15，每题采样两次。按文件顺序从官方训练和评测划分取题，留出题与训练文件中任一题的题号、盘面和答案盘面均无完全重复。开发与留出使用两组不同的解码种子。Mask15 留出的两道题曾用于作者 checkpoint 的三批配对评测，本轮聚合权重由开发题得分确定。题目 ID、候选种子与解码设置见运行清单。

## 解出局数

每格有四局，括号内为两个采样种子各解出的局数。

| 模型 | 开发 Mask5 | 开发 Mask15 | 留出 Mask5 | 留出 Mask15 |
|---|---:|---:|---:|---:|
| 中心 | 1（1、0） | 0 | 1（1、0） | 0 |
| 方向 1 | 1（0、1） | 0 | 0 | 0 |
| 方向 2 | 0 | 0 | 0 | 0 |
| 方向 3 | 0 | 0 | 2（1、1） | 0 |
| 方向 4 | 2（1、1） | 0 | 0 | 0 |
| 标准 ES 更新后的中心 | — | — | 1（1、0） | 0 |

标准 ES 聚合写入了权重。从原中心重放聚合后，所选浮点张量的哈希一致。四个方向在留出阶段分别从原中心重建，重建权重的哈希与开发阶段逐一一致。两份中心在留出集的 8 个题目与采样种子配对上，1 局同时成功，7 局同时失败。

## 轨迹观察

开发集没有选出在两种难度间表现交叉的候选对。方向 4 在开发题上两次解出同一道 Mask5，方向 3 为零分。到了留出集，方向 4 零分，方向 3 两次解出同一道 Mask5。每组只有两道题，现有记录无法分清题目差异和采样波动的贡献。

44 局 Mask15 全部填满且全部有行、列或宫冲突。首次冲突的中位动作轮次为开发第 2 轮、留出第 3.5 轮。例如开发题 `train-000006` 在第一个种子下，四个方向第一步都填了 `r1c1=5`，与同宫已有的数字冲突。终局 0/1 奖励在这次 Mask15 样本上无法区分方向。此处只按空格数区分难度，现有数据尚不足以判断是否存在可迁移的能力互补。

## 数据与复算

本地 `runs/observable-es-01/` 保存运行清单 `manifest.json`、`development.json`、`update.json`、`summary.json`、22 份包含逐动作轨迹的评测 JSON，以及 88 行的 `scores.csv`。对照清单重新从轨迹复算，逐题成绩与矩阵和汇总一致。运行入口见 [实验 README](../README.md)，既有三批 checkpoint 复评见 [复现观察](复现观察.md)。
